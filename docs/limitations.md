# 局限与不声称的东西

这份文件存在的意义：防止我自己在简历和面试里说过头。

## 不声称

| 不说 | 为什么 |
|---|---|
| 通过了功能安全认证 | 没有认证机构、没有真实风险评估、没有 PL/SIL 论证。声称了就是硬伤 |
| 真机安全 | 全程仿真，没有硬件。sim-to-real 的差距完全没碰 |
| 力限制 / 功率限制 | 没测碰撞力、没做柔顺控制 |
| 感知安全 | 没有真实视觉，目标是直接给的世界坐标 |
| 性能 | 没测延迟、吞吐、长时稳定性 |

## 明确的简化

1. **抓取是 kinematic carry**：夹爪闭合后，方块位姿被直接写成跟随 TCP，不走接触力学。
   好处是确定、快、不引入接触求解噪声；代价是"抓不住会滑"这类失败模式测不到。
   代码位置：`executor._sync_carried`。

2. **单场景、单物体**：一张桌子、一个方块、一个臂。多物体堆叠、遮挡、动态障碍都没做。

3. **IK 用阻尼最小二乘**，没有轨迹优化，没有动力学约束（速度/加速度上限只在策略层粗略体现）。

4. **human zone 是纯视觉 geom**（`contype=conaffinity=0`）：物理上挡不住机械臂，只有策略层能拦。
   这是刻意的——它正好用来证明"物理拦不住的东西只有策略能拦"。但也意味着如果在策略层留了洞，仿真不会兜底。

5. **场景几何是常量**：`ZONE_CENTER/ZONE_HALF` 在 `scene/build.py`，`policy.yaml` 里有一份对应的数字。
   两处必须手工保持一致，没做自动校验。这本身就是一个待修的隐患。

## 可迁移性

能迁移到真机的部分：gate 的判定逻辑、审批 token 机制、判决与原因码的定义、测试用例设计、审计字段设计。
不能迁移的部分：任何涉及力、摩擦、延迟、感知噪声的结论。
