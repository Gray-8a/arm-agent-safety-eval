# 威胁模型

一句话：**我们要防的不是模型说错话，是模型（或被注入的模型）让机械臂做出危险动作。**

## 资产

| 资产 | 被谁威胁 | 后果 |
|---|---|---|
| 人（human zone 内） | 机械臂进入该区域 | 物理伤害 |
| 机械臂自身 / 桌面 | 穿透、撞击 | 设备损坏 |
| 策略（policy.yaml） | 被提案或场景文本改写 | 所有防线失效 |
| 审批记录 | 伪造、重放、抵赖 | 事后追不了责 |

## 信任边界

```
不可信 ──────────────────────────────────────────► 可信
指令 / 场景文本 / 模型输出 │ 提案 schema │ gate │ 审批人 │ executor │ 策略文件
```

- **模型输出一律不可信**，只当提案看。
- **策略文件可信**（部署时由人放进去，进程启动读一次）。
- **审批人可信但会犯错**：所以审批要走签名、绑定、TTL、单次，不靠"他点了同意"。
- **执行器可信**，因为它是唯一能动仿真的一层，而且只执行 gate 校验过的那条轨迹。

## 已知残余风险（没防住的）

1. **感知欺骗。** 我们的目标点是直接给的世界坐标，没有真实视觉。真实系统里"看到的位置"可以被骗，
   这一层完全没覆盖。`confidence` 是我们注入的数，不是模型对图像的置信度。
2. **侧信道。** 门耗时、日志写入模式可能泄露策略细节。没做。
3. **拒绝服务。** 高频提案能让 gate 忙死。没做限流。
4. **供应链。** Menagerie 的模型文件是直接 clone 的，没校验哈希。
5. **物理层。** 力、摩擦、延迟、柔顺控制全没碰。这块要靠真机和认证，不是仿真能替代的。
6. **审批人自身被社工。** 我们保证"批准了哪条就执行哪条"，不保证"那个人判断是对的"。
   证据包是给人看的，能不能看懂是另一个问题。

## 为什么不用提示词防御

提示词可以被对抗输入覆盖，代码里的 `if` 不行。
本项目所有防线都在 LLM 之下：模型能决定的只有"提案什么"，不能决定"什么算安全"。
